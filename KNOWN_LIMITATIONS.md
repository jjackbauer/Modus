# Known limitations — Wip.Factory v0.4 engineering candidate

This list is part of the version-bound delivery record. It is not an acceptance verdict.

- **Independent acceptance is historical and failed.** The 2026-11-19 independent attempt recorded PA-01 `fail`, PA-02 `pass`, and pair `fail`. That outcome is preserved verbatim in `ENGINEERING_TEST_RESULTS.json` and is not re-adjudicated by this engineering milestone. The current candidate is **NOT_ACCEPTED**.
- **Engineering completion is not acceptance.** `ENGINEERING_COMPLETE` means the mandatory engineering gates in this repository passed. It does not mean the product was independently accepted, is production ready, or that any spent acceptance task may be reused.
- **No new blind acceptance was performed.** The task explicitly excludes independent product acceptance. The known-input and remediation artifacts under `docs/goal-wip-factory-operator-alpha/` remain historical evidence, not new certification.
- **DSH bounded projection is a diagnostic, not an equivalence claim.** The session-budget instrument reports a 4,745-byte per-turn projection against an 11,638,913-character transcript (99.96% smaller). That projection preserves turn facts and seq locators, not the full conversational context; it is a working-state reconstruction aid, not proof that the same session would have completed with 1,187 tokens.
- **DSH evidence lives in a separate checkout.** The harness changes are committed at `C:\Users\ricar\deepseek-harness` commit `ef7cb1377d` on `feature/dsh-engineering-instrumentation`. Its pre-commit hook could not run in this environment (`msys` process-creation failure); typecheck (`tsc -b tsconfig.host.json`, exit 0) and the named Vitest suites were run directly.
- **Partial or mismatched worktrees are preserved, not auto-salvaged.** A directory that exists but is not a registered Git worktree is refused with `worktree-partial` and left untouched; a worktree on another branch is refused with `worktree-mismatch`. This preserves uncommitted work but requires an operator (or a later explicit repair) to resolve the layout.
- **Orphan-branch recovery infers one baseline.** When a session branch exists but no durable state does, the original target is reconstructed as the merge-base with the target branch and recorded with `BaselineSource=inferred-merge-base`. A rebase performed before any state existed cannot be distinguished from legitimate work in that narrow path; once state exists, `worktree-history-rewritten` refuses a rewritten head.
- **Architecture conformance is intentionally closed.** It classifies SDK-style projects from structural MSBuild facts (SDK identity, `OutputType`, test-provider package references, `IsTestProject`, ASP.NET Core framework references, entry-point evidence). Central `Directory.Build.props` target frameworks are supported; classification properties hidden in a conditional/explicit import, `Directory.Build.props` override, or `Directory.Build.targets` are refused as ambiguous rather than interpreted.
- **Crash injection during the Git merge syscall is not covered.** The existing deterministic in-process crash tests cover crash-after-merge and post-merge re-verification; an OS kill during the merge system call itself remains untested.
- **Process identity proof is Windows-only.** Other platforms report `unsupported-platform` rather than guessing.
- **Review architecture/security checks are narrow by design.** They enforce the supported single-repository ASP.NET Core .NET 10 shape and a static alpha security policy; they are not a general vulnerability scanner.
- **The candidate manifest binds a clean source revision.** Generated evidence files are committed after the code commit they describe; the manifest records the code revision and the digests of the evidence artifacts, not a circular evidence-commit hash.
