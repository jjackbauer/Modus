## What changed

### 1. Structural architecture conformance (P0)

`WIP/Wip.Factory.Host/Factory/FactoryReviewChecks.cs` now classifies each project from structural MSBuild facts:

- Project SDK identity (`Microsoft.NET.Sdk`, `.Web`, `.Razor`, `.Worker`, Blazor WebAssembly, `MSTest.Sdk`).
- Effective `OutputType` (explicit or SDK default), rejecting `WinExe`, unknown values and executable
  non-web/non-test projects.
- Test-provider declarations (`IsTestProject`, `Microsoft.NET.Test.Sdk`, xUnit, NUnit, MSTest, TUnit,
  Microsoft.Testing.Platform) instead of the `*.Tests` filename.
- ASP.NET Core `FrameworkReference` plus executable output as a web application.
- Entry-point evidence (`Program.cs`, `StartupObject`), so a test-declared executable with a user entry
  point is refused as a disguised executable.
- Conditional properties, explicit imports, `Directory.Build.targets` overrides and inherited classification
  overrides as ambiguous; the nearest `Directory.Build.props` target framework is still supported.
- Exactly one web application; libraries and test projects are permitted.

The evidence digest now binds a deterministic manifest of relative paths and classifications rather than an
absolute worktree path. Review policy versions were bumped to `factory-review-checks@3` and
`architecture@3`.

Adversarial tests: `WIP/Wip.Factory.Host.Tests/ArchitectureConformanceTests.cs` (22 cases) plus the existing
`FactoryBoundaryTests.cs` architecture cases.

### 2. Worktree recovery and retry hardening (P0/P1)

`WIP/Wip.Workspaces.Git/WipWorkspaceProviderGit.cs` and `WorkspaceProvisioningState.cs` now:

- Persist the session's original target commit, branch, worktree path, last observed head and an append-only
  attempt list under the repository Git directory (never in the working tree).
- Reuse a valid worktree without reset/clean/rebase, attach an existing branch, prune a stale registration,
  repair a partial worktree when Git can, and preserve any unrepairable directory with a named
  `worktree-partial` refusal.
- Serialize concurrent retries with an in-process semaphore plus an OS-exclusive per-session file lease.
- Refuse branch/path/repository mismatches, corrupt state, a session branch that no longer descends from the
  original target, and a recorded head that is not an ancestor of the new head.
- Report target-branch advancement as `TargetHasAdvanced`/`ObservedTargetCommit` while keeping
  `TargetCommitAtCreation` unchanged.
- Record the session head after a successful implementation commit (`RecordSessionHeadAsync`), so a later
  silent rewrite is detectable.

`ImplementationAttemptJournal.cs` persists one checksummed record per implementation attempt and links each
retry to its predecessor. `RealModelImplementationRunner` now records every outcome, including provisioning
failures, with `FailureRole=original|retry`; a later retry failure cannot replace the original agent failure.

Executable recovery/concurrency tests: `WIP/Wip.Workspaces.Git.Tests/Git/WorktreeRecoveryTests.cs` (14 cases)
and `WIP/Wip.Factory.Host.Tests/ImplementationAttemptJournalTests.cs` (6 cases).

### 3. Version-bound engineering delivery record (P1)

`WIP/Wip.Factory.Host/Factory/EngineeringDeliveryRecord.cs` defines `factory/engineering-delivery@1` and
`factory/candidate-manifest@1`. The record:

- Derives `ENGINEERING_COMPLETE` / `ENGINEERING_BLOCKED` from the build result, executed suite counts and
  mandatory engineering gates.
- Rejects `ACCEPTED`/`PRODUCTION_READY` as engineering statuses and refuses independent acceptance as a
  mandatory engineering gate.
- Requires per-suite executed/passed/failed/skipped counts, TRX digests, a build digest, a source revision and
  known limitations.
- Keeps a separate historical acceptance record (PA-01/PA-02/pair plus evidence digest) that cannot raise the
  engineering status.
- Recomputes and verifies a SHA-256 content digest on read, so a hand-edited metric is refused.

The product CLI gained `factory engineering record|manifest --input <json> --output <json>`; the gate script is
the only writer of the checked-in JSON, and it measures the counts from TRX files.

Tests: `WIP/Wip.Factory.Host.Tests/EngineeringDeliveryRecordTests.cs` (17 cases).

### 4. DSH-scoped efficiency instrumentation (P1)

Delivered in the separate DSH checkout (`C:\Users\ricar\deepseek-harness`, branch
`feature/dsh-engineering-instrumentation`, commit `ef7cb1377d`):

- `scripts/session-budget.ts` reads a v4 session archive, measures model calls, tool calls, retries, cache
  split, wall time and cost (unknown when usage is incomplete), detects repeated/stalled tool-call groups, and
  emits a bounded per-turn projection with source/projection digests and on-demand seq locators.
- `scripts/engineering-deliverables-gate.ts` provides a synchronous `GoalCompletionCheck` that refuses a goal
  completion when a required engineering deliverable is missing, empty, escaping, malformed or carries the
  wrong status. The integration test drives the real `GoalService` and proves no `goal/change` commit occurs.
- The reproducible baseline is the frozen prior session archive
  (`sha256:93d0249a…`): 515 model calls, 586 tool calls, 217,628,655 aggregate tokens (216,914,304 cache-read),
  8,614 s wall time, $1.4273 at pinned DeepSeek Flash rates. The bounded projection is 4,745 bytes versus
  11,638,913 transcript characters (99.96% smaller); this is a working-state reconstruction, not an
  equivalence claim.

Existing DSH mechanisms used rather than duplicated: compaction and tool-result pruner, work-state/session
trace, spill/output views, the repeat-tool-reminder guard, delegation stagnation, and the goal completion gate
service. Verification: 16 new focused tests, 47 tool-subagent capability tests, 20 repeat-guard tests, 36
work-state/session-trace tests, and `tsc -b tsconfig.host.json` exit 0.

Evidence: `docs/goal-wip-factory-operator-alpha/engineering/DSH_EFFICIENCY_EVIDENCE.json`,
`DSH_EFFICIENCY_BASELINE.json`, `DSH_EFFICIENCY_BASELINE.md`, `DSH_CONTEXT_PACK.json`.
