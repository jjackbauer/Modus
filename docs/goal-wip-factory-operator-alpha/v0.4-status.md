## What blocks acceptance (exact next actions)

1. An independent evaluator supplies two behaviorally different, previously withheld ASP.NET Core HTTP requirement
   files and two expectation manifests:

   ```json
   {
     "gate": "PA-01",
     "expectedScenarioIds": ["AC-1", "AC-2", "..."],
     "approvedContractDigest": "sha256:<evaluator-approved frozen contract>",
     "frozenHostDigest": "sha256:<binary from this revision>",
     "requireLiveModel": true,
     "evaluatorOwned": true,
     "evaluatorId": "<evaluator identity>"
   }
   ```

2. Run the unchanged binary twice:

   ```powershell
   run-acceptance.ps1 -Requirement <A.md> -Gate PA-01 -OutRoot <dir> -Expectations <A.json>
   run-acceptance.ps1 -Requirement <B.md> -Gate PA-02 -OutRoot <dir> -Expectations <B.json>
   factory acceptance verify-pair --first <A.evidence.json> --first-expectations <A.json> `
                                 --second <B.evidence.json> --second-expectations <B.json>
   ```

3. Attach both evidence manifests and the pair verdict. A failed attempt is recorded as failed; a changed binary or
   contract requires a new freeze and new unseen tasks.

The harness refuses a contract whose digest differs from `approvedContractDigest`; it also refuses empty, missing,
duplicated, failed or unexpected scenario results, mock evidence for a blind gate, a changed host binary, and
known-input evidence labelled blind.
