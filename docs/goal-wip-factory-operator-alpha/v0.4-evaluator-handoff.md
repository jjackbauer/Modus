# Independent acceptance handoff (PA-01 / PA-02)

This is the handoff package for an evaluator who was not involved in the implementation. It deliberately does not
contain the blind requirements, which the evaluator authors and withholds until the frozen artifacts below are
recorded.

## 1. Frozen artifacts

| Artifact | Value |
|---|---|
| Repository | `jjackbauer/Modus` |
| Branch | `feature/wip-factory-alpha` |
| Code revision | `c2946c9` (v0.4 remediation; harness exit-code fix `fe45fac` is script-only) |
| Host binary | `WIP/Wip.Factory.Host/bin/Debug/net10.0/Wip.Factory.Host.dll` |
| Host binary digest | `sha256:<evaluator-measured>` |
| Effective config digest | `sha256:<evaluator-measured>` |
| Model/provider | configured `deepseek-chat` through the existing `DeepSeekCredentials` path; no secrets in evidence |
| Acceptance harness | `docs/goal-wip-factory-operator-alpha/run-acceptance.ps1` at this revision |
| Evaluator verdict tool | `factory acceptance verify` / `factory acceptance verify-pair` at this revision |

The evaluator should measure the host and config digests **before** revealing either requirement, record them in both
expectation files, and rerun the pair without rebuilding or editing source/config.

## 2. What the evaluator supplies

Two requirement documents, each in the repository's supported form (ASP.NET Core HTTP on .NET 10, single repository,
`## Acceptance expectations`), plus one expectation file per gate:

```json
{
  "gate": "PA-01",
  "expectedScenarioIds": ["AC-1", "AC-2"],
  "approvedContractDigest": "sha256:<evaluator-approved contract for this requirement>",
  "frozenHostDigest": "sha256:<host binary measured before reveal>",
  "requireLiveModel": true,
  "evaluatorOwned": true,
  "evaluatorId": "<evaluator identity>"
}
```

The expected scenario IDs and contract digest are the evaluator's, not the implementation's. The harness will refuse
to approve a proposal whose digest differs, and will refuse evidence with missing, duplicated, extra, failed or
mock-produced scenarios.

## 3. Execution

```powershell
docs/goal-wip-factory-operator-alpha/run-acceptance.ps1 -Requirement <A.md> -Gate PA-01 `
    -OutRoot <evidence-root> -Expectations <A.evaluator.json>

docs/goal-wip-factory-operator-alpha/run-acceptance.ps1 -Requirement <B.md> -Gate PA-02 `
    -OutRoot <evidence-root> -Expectations <B.evaluator.json>

dotnet run --project WIP/Wip.Factory.Host --no-build -- factory acceptance verify-pair `
    --first <evidence-root>/PA-01.evidence.json --first-expectations <A.evaluator.json> `
    --second <evidence-root>/PA-02.evidence.json --second-expectations <B.evaluator.json>
```

Each run exits non-zero unless the evaluator's expected scenario set is complete and passing in both the pre-merge
and post-merge phases, on the same frozen host/config, with live-model evidence.

## 4. What the implementer will not do

- Will not author, inspect, tune against, or relabel the two blind requirements.
- Will not modify the host, prompts, contract, or profile between the two runs.
- Will not convert `acceptance-pending` to `accepted` on green unit tests alone.
- Will publish a failed attempt as failed, not retry silently.

## 5. Returned evidence

- `PA-01.evidence.json`, `PA-02.evidence.json` (evaluator-shaped evidence, no requirement text).
- `PA-01.verdict.json`, `PA-02.verdict.json` and the pair verdict.
- The exact commands and exit codes recorded in each evidence file.

Until this exchange happens, the factory remains **implementation-ready / acceptance-pending**.
