### 2.5 Verified passes (not findings)

- **Tabs**: Live, Replay, Strategies and Ledger all work by mouse and by `1`–`4`; at 390 all four buttons fit (x 15–292).
- **Cards**: replay hand 1 contains all four suits (K♠, J♦, 10♣, A♣, 5♠, J♥, 4♥, 10♦, J♣); glyphs and red/black colours are correct, `T` renders "10", and every face has the right `aria-label` (also exposed as "generic|King of spades" etc. in Chromium's accessibility tree). The empty board slot is dashed and labelled; the face-down back is striped and labelled.
- **Hand-strength labels**: replay hand 1 (one pair Jacks / two pair Jacks and Tens), replay hand 5 (two pair Sevens and Threes / full house Threes full of Sevens) and the flop sampled by the provided `live 42 10 200` command's text probe (one pair Aces / high card Ace) all match a hand computation from the displayed board and hole cards.
- **Replay scrubber**: hand 1 of 20, hand 5 of 5 and the provided hand 2 of 5 show the same hand number in the slider label, table title and board as `GET /api/sessions/{id}/hands/{n}`; ArrowLeft/ArrowRight step the hand number and content; a four-card board renders four faces plus one empty slot.
- **Strategies**: four entries, the champion is selected by default, the "CHAMPION" pill is visible in the list and the detail, and the parameters/prompt are readable at 1440 and 390.
- **Ledger at 1440**: nine headers fit without wrapping (measured header scrollWidth == clientWidth for every header), numeric cells are right-aligned, and the three rows are legible; the 390 limitation is RV-08.
- **390 page**: no page-level horizontal scroll (`documentElement.scrollWidth` 390); the ledger is the only horizontally scrolling region (RV-08); the live/replay tables and action log fit.
- **Console/network**: 0 console errors, 0 page errors, 0 responses >= 400, and only `http://127.0.0.1:5099` requests across all interactions.
- **Focus**: keyboard focus rings are visible in practice (white adaptive ring on the Strategies tab, [review-focus-tab.png](review-focus-tab.png)); card red 6.47:1 and muted text 7.42:1 on the dark background; heading order is h1 → h2 → h2/h3 with no skipped level.
- **Injection**: no `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` or `eval` in `app.js`/`index.html`/`viewer.css`; all artifact text uses `textContent`/`createElement`, and the server-rendered `/viewer/table` fragment uses `WebUtility.HtmlEncode`. No external URL in any asset.

## 3. Verdict

**No.** The viewer is broadly functional and the 1440 views of the table, replay, strategies and ledger are readable, but it should not be shown to a user as-is: the live table highlights the player who just acted rather than the player to act (**RV-01**), and its action log silently mixes hands (**RV-02**). RV-03/RV-04 also corrupt the hand-resolution story by showing a zero pot at the moment the pot is awarded. Blocking findings: **RV-01, RV-02**.

## 4. notChecked

- **Empty Strategies / Ledger / session list with no artifacts**: not exercised; the populated data directory was used and the empty live state is the only empty state exercised. A separate data directory would be needed to see "No strategies recorded yet" / "No promotions yet".
- **Real screen reader**: only Chromium's accessibility tree and DOM attributes were inspected; no NVDA/JAWS/VoiceOver run.
- **Firefox and WebKit**: Chromium 1155 only.
- **Replay scrubber response-ordering race**: 12 natural click-then-drag attempts were clean; an injected 1.5 s delay on the hand-1 response produced a mismatch (slider at 5, label "Hand 1 of 20"), but this required a synthetic per-request delay, so it is not filed as a finding.
- **Live retention cap / long matches**: maximum observed was 21 action rows; the 200-action retention and 500-hand maximum were not stress-tested.
- **Hostile artifact injection**: no hostile strategy/session file was written because the data directory is read-only in this review; the injection check is source-level (no HTML sinks) plus the existing offline/no-innerHTML test.
- **Touch/real mobile device**: only viewport emulation; no touch gestures or device scrollbars.
- **`/viewer/table` server fragment layout**: source-read and used by the tests, but not linked from the SPA; its visual page layout was not reviewed.
- **Recorded-history correctness itself**: I treated `potAfter`/`amount` (zero for calls/folds/all-ins and zero after settlement) as the data contract; the findings above concern how the viewer presents those values, not whether the engine/history should record them differently.
